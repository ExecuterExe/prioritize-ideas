# Приоритизация идей

Сервис для учебной команды: каждый молча предлагает проблемы или идеи, команда склеивает
дубли, договаривается о критериях, оценивает вслепую и видит, где согласна, а где спорит.
Методология и план — в [PLAN.md](PLAN.md).

## Что умеет

- **Два входа:** «⚡ Быстрая командная работа» (цель → запуск за минуту, лишние инструменты спрятаны в «Ещё инструменты») и «🛠 Полноценная проектная работа» (всё ниже).
- **«Что дальше?»** после результатов: продолжить, свернуть на другой путь (переформулировать, искать другое, идеи, карта пути, предположения), переоценить заново или завершить — прошлые этапы и оценки сохраняются, путь проекта попадает в отчёт.
- **Пульт ведущего:** кто пишет, кто отправил, кто пропал со связи; запас времени переходит на следующий шаг, при опоздании — кнопка «Сократить»; «📴 Перейти на один экран», если Wi-Fi подвёл.
- **Сценарии работы:** «Классика» (проблема → идея), «Sprint-lite» (карта пути → проблема → идея),
  «От гипотез», «От трендов», «Классика + pre-mortem», «Проверка концепции», «MVP-доска» или свой.
- **Конструктор шаблонов карточек:** 11 типов полей, обязательные и условные поля, подстановка из прошлого этапа.
- **Паспорт задания:** вставьте текст задания — он разложится по разделам; проверка соответствия результата.
- **Слепая оценка** с картой разногласий, калибровкой шкал, вторым раундом и проверкой устойчивости лидера.
- **Развитие идей:** чужие карточки по кругу, «развить» и «объединить», дерево происхождения.
- **Предположения и эксперименты:** карта «важность × доказанность», тест-карточки с авто-выводом.
- **Pre-mortem**, **карта пути пользователя**, **сценарии «что если»**, **MVP-доска**, **«Кто что делает»**.
- Экспорт: текст для Lean Canvas, отчёт в Markdown, печать/PDF, файл проекта, список задач для чата.

Подробности — в [METHODOLOGY-2.md](METHODOLOGY-2.md) и [METHODOLOGY-3.md](METHODOLOGY-3.md).

## Как запустить

### На паре с телефонами (основной режим)
Сайт должен лежать на GitHub Pages (см. «Публикация»). Тогда:
1. Откройте адрес сайта на ноутбуке → «Новый проект» → «⚡ Быстрая командная работа» → цель → «📱 С телефонов».
2. Покажите QR-код команде (или «Скопировать ссылку для чата»).
3. Ведите сессию кнопкой «Дальше →». Свои карточки и оценки ставьте во вкладке «Мой голос».

Пока сайт не опубликован, можно запустить его с ноутбука:

```bash
npm run dev
```

Откройте http://localhost:5173. Телефоны смогут войти, только если они видят ноутбук в сети:
`npm run dev` показывает адрес вида `http://192.168.x.x:5173`. В вузовском Wi-Fi это часто
заблокировано, поэтому для занятий нужен GitHub Pages.

### Без интернета — «Один экран»
Откройте файл `PrioritizeIdeas-offline.html` двойным щелчком (лучше в Chrome или Edge).
Все работают на ноутбуке по очереди, чужие ответы скрыты «шторкой».
Пересобрать файл: `npm run build:single`, затем скопировать `dist-single/index.html`.

## Как устроена связь
Телефоны и ноутбук обмениваются зашифрованными сообщениями (AES-GCM) через несколько
публичных Nostr-релеев одновременно. Ключ шифрования есть только в части ссылки после `#`,
он не попадает ни на GitHub, ни на релеи. Все данные хранятся в браузере ноутбука
организатора. Вкладка «Связь» показывает состояние релеев.

Проверить релеи из текущей сети:

```bash
npm run probe
```

## Публикация на GitHub Pages
1. Создайте пустой репозиторий на GitHub и отправьте туда этот проект (ветка `main`).
2. В репозитории: Settings → Pages → Source: **GitHub Actions**.
3. Каждая отправка в `main` запускает тесты, сборку и публикацию (`.github/workflows/pages.yml`).

## Разработка
- `npm test` — тесты: математика, движок этапов, протокол (с потерей 30% сообщений).
- `npm run typecheck` — проверка типов.
- Код: `src/core` — модель, расчёты, движок; `src/net` — шифрование, релеи, протокол;
  `src/ui` — интерфейс; `src/store` — хранение.
